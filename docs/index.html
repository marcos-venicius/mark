A Markdown viewer with exactly one job

mark <file> opens a window, renders that file, and stays out of the way. No editor, no preview pane, no browser tab. It highlights the code, shows the images, and reloads when you save.

Architecture

A ```mermaid fence is drawn where it stands, by a renderer compiled into the binary. No network, no plugin.

Each diagram is drawn twice, once per palette, and the stylesheet shows one — which is also what makes a dark page printable.

Formulas

$x$, $$x$$ and a ```math fence, typeset by a KaTeX compiled in beside the diagram renderer.

Inline as well: the golden ratio is φ = 1 + √52, set in the middle of a sentence without disturbing the line.

What it renders

Everything a README throws at it

The parts most viewers leave to a plugin, a CDN or a browser tab are compiled into the binary and work with the network unplugged.

Mermaid diagrams

A ```mermaid fence is drawn where it stands by a renderer compiled into the executable — no network, no plugin, no export step. Click one to drag it about, zoom it, and copy it as a PNG. A fence that will not parse keeps its source and says why.

Maths, typeset properly

$x$, $$x$$, $`x`$ and a ```math fence, laid out by a bundled KaTeX. A formula that will not parse is written out where it stands rather than swallowed.

Live reload that keeps your place

Save in your editor and the window updates. A save is told apart from a read — rendering opens the file too — and your scroll position survives the round trip.

Syntax highlighting

The language set bat uses, so TSX, TOML and Dockerfile are covered. Each block is labelled and carries a copy button.

Images, local or remote

Local paths resolve against the document, including ones that point up a directory — where a plain webview would give up.

GitHub alerts

> [!NOTE], [!TIP], [!IMPORTANT], [!WARNING] and [!CAUTION], each in its own colour.

A table of contents

In the sidebar, tracking the section you are reading. It appears once a document has three headings, and T puts it away — for next time too.

Links between documents

A relative link to another .md opens in the same window, at the heading it names, with back and forward history. Web links go to your browser.

GFM and front matter

Tables, task lists, strikethrough, autolinks, footnotes, description lists and superscript. YAML front matter is hidden, not printed.

Typography that travels

Inter for text and JetBrains Mono for code, compiled in, so a document reads the same on a machine that has neither installed.

Five themes

Light, dark, Catppuccin Mocha and Gruvbox Dark, or the system, which it follows and switches with while the window is open. D walks them and the choice is remembered between runs. The syntax colours change with the page.

Find, print, zoom

Find in page with next and previous, Ctrl P to print or save a PDF, and zoom that sticks to the document.

Install

Two systems, no ceremony

Both routes end with mark in your Open with menu for .md, .markdown, .mdown, .mkd, .mkdn and .mdx.

1 The two libraries

The window is a native WebKitGTK view. At runtime only libwebkit2gtk-4.1-0 is needed, and most desktops already have it — it is what GNOME's own apps use. 

$ sudo apt install libwebkit2gtk-4.1-dev libsoup-3.0-dev

2 Build and install

Rust 1.85 or newer. install.sh builds in release mode and registers mark with the desktop: the binary, an icon, a .desktop entry and a MIME package. 

$ git clone https://github.com/marcos-venicius/mark.git
$ cd mark
$ ./install.sh

3 Open something

The prompt comes back in about 30 ms — mark hands the terminal straight back, so closing it does not take the window with it. ./uninstall.sh removes all five files again. 

$ mark README.md

Set PREFIX to install elsewhere. Everything follows it, the data directories included; the default is ~/.local. Or take the binary alone with cargo build --release and no desktop entry at all.

1 Nothing to install first

The window uses WebView2, which ships with Windows 11 and is a bootstrapper away on Windows 10. There is no runtime to chase and no Visual C++ redistributable.

2 Take the installer

mark-setup-x64.exe installs for the current user only — %LOCALAPPDATA%\Programs\mark, no administrator prompt, a Start Menu entry, and an uninstaller that takes the registry keys with it. Or take the single .exe and run it from anywhere.

Installer (x64) Plain .exe

3 Double-click a file

Installing puts mark in the Open with menu of every Markdown extension. The installer leaves PATH alone; add %LOCALAPPDATA%\Programs\mark to it if you want mark file.md from a terminal.

No installer can make itself the default for a file type, and this one does not pretend to: on Windows the value that decides it is hash-protected, precisely so that programs cannot claim a file type behind your back. Choose mark once with "Always use this app" and the double click works from then on.

Both downloads are the newest version, and the links follow each new one on their own — see what is in each. There is no published Linux binary; that side builds from source.

How it works

One binary, four files

There is no bundled browser and no frontend build step. The stylesheet and the page script are compiled into the executable along with everything else it draws with.

It borrows the system's renderer

WebKitGTK on Linux, WebView2 on Windows — the engine your desktop already ships. That is how 4.6 MB is enough for a viewer that draws diagrams and typesets formulas.

A scheme of its own

The document is served over mark:// rather than file://, and relative URLs are made absolute while the Markdown is rendered — so an image a directory up is still found.

Paid for only when used

The diagram and formula renderers are stored compressed and inflated the first time a document turns out to need one. A document with neither pays for neither.

Locked down, because documents bring HTML

The page runs under a Content Security Policy that permits local assets and remote images and nothing else: no scripts from the document, no outbound requests. The protocol handler serves only file types a renderer has a reason to load. 

mark <file>
  |
  |-- render.rs     Markdown -> HTML
  |-- protocol.rs   the mark:// scheme
  |-- watcher.rs    watch -> live reload
  '-- main.rs       window, webview, history
